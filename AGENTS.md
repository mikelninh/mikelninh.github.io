# Agent instructions — Michael Ninh portfolio

Before changing any portfolio, CV-supporting or application-proof page, read `PORTFOLIO_STANDARD.md`.

## Non-negotiable

The hiring path must be understandable and usable in **30–60 seconds**.

Default to:

**identity → question/problem → interaction/proof → evidence/result → boundary → next action**

Do not add sections merely because more information exists. Technical depth belongs behind progressive disclosure.

### Hard limits

- Main portfolio: 3 featured proofs maximum.
- Targeted application page: 1 primary proof, at most 1 supporting proof.
- A recruiter should not need to read an architecture essay before trying the product.
- Prefer a clickable/testable experience over descriptive case-study prose.
- If a page becomes long, remove or hide information before shrinking typography.
- Keep CV, GitHub/code and contact obvious.

The goal is not to show everything Michael has built. The goal is to make the strongest evidence impossible to miss.
