# Michael Ninh Portfolio — Agent Guide

This repository is Michael's public professional trust surface. It should help recruiters, collaborators and potential employers understand what he has built, what he can own today, where he is growing and how to verify the evidence.

## Who this repository serves

- recruiters and hiring managers scanning quickly for credible fit;
- engineers, product leaders and collaborators inspecting project evidence;
- people using assistive technology, mobile devices or translated context;
- Michael, whose reputation and livelihood are affected by every claim;
- project collaborators whose work must not be misrepresented;
- AI agents helping maintain copy, links, accessibility and evidence.

The portfolio is designed with AI agents but remains accountable to human readers. Agents must not invent achievements, metrics, employers, endorsements or production experience.

## North star

Turn ambiguity into trustworthy proof: make the most relevant evidence easy to find, the limitations easy to understand and the next conversation easy to begin.

## Content invariants

1. Evidence before confidence. Every specific result should be traceable to a repository, live artifact, evaluation or clearly labelled demonstration.
2. Distinguish shipped work, prototypes, active pilots, concepts and future direction.
3. Preserve the honest fit: capable now, explicit growth areas, no inflated seniority.
4. Lead with applied AI and humane systems; playful and speculative work may enrich the picture without obscuring professional relevance.
5. Do not expose private family, health, relationship, application or account information.
6. Do not attribute collaborative work solely to Michael when material contributors should be named.
7. Accessibility, responsive layout, readable hierarchy and working links are part of correctness.
8. Match the existing editorial visual language unless a redesign is the task.

## Repository orientation

- `index.html` — primary portfolio narrative and selected case files.
- `assets/` — shared visual styling and assets.
- project and application subdirectories — deeper evidence and tailored views.
- `package.json` — local Vercel development command.

Inspect the relevant project repository before changing technical claims about that project.

## Working boundaries

Agents may independently fix broken links, accessibility defects, semantic markup, responsive issues, typos and clearly outdated repository references when the replacement is verifiable.

Require Michael's approval before:

- changing his role positioning, availability, salary, location or career goals;
- adding or removing major case studies;
- publishing personal contact details beyond those already public;
- claiming commercial impact, user numbers, production deployment or external validation;
- changing the main visual identity or deploying the site.

## Local review

```bash
npm install
npm run start
```

Review the homepage at narrow mobile and desktop widths. Check keyboard navigation, focus visibility, heading order, contrast, link destinations, metadata and the first ten-second recruiter scan.

## Definition of done

A change is ready for review when every material claim is supportable; project status is labelled honestly; the main message remains clear within seconds; no private information was introduced; relevant links work; and the page remains accessible, responsive and recognisably Michael.
