Die eigentliche Integrationshürde sichtbar machen

Ein Pilot scheitert selten daran, dass ein JSON-Endpoint fehlt. Häufiger tauchen Fragen seriell auf: Datenschutz? Betriebsrat? Lizenz? IT-Security? Einkauf? Medizinprodukt? Verantwortlicher Mensch? OpenAction macht daraus einen Approval Graph, damit Verantwortliche früh sehen, was wirklich blockiert und was parallel geprüft werden kann.

1

Action Contract

Was soll passieren, warum, aufgrund welcher Evidenz und mit welchen Berechtigungen?

2

Approval Path

Wer muss zustimmen? Welche Nachweise fehlen? Was ist blocker vs. optional?

3

Outcome

Wurde die Handlung wirklich ausgeführt und hat sie den gewünschten Effekt erzeugt?

Mit Approval Path

Ein Trust Passport: Zweck, Datenfluss, Modell, Lizenzen, Security, Evals.
Parallelisierung: Privacy, Security, Workforce und Procurement starten früh.
Bounded pilot: sichere Testgrenzen werden explizit definiert.
Owner pro Gate: kein „wer ist eigentlich zuständig?“.
Decision record: nachvollziehbar, wer was wann freigegeben hat.

Super simpel integrieren

const action = OpenAction.create({
  kind: "health.follow_up.coordinate",
  label: "Follow-up koordinieren",
  reason: "FHIR Task verlangt Follow-up",
  evidence: [{ kind:"system", source:"FHIR", locator:"Task/123" }],
  risk: "high",
  approval: { required:true, mode:"qualified_human", status:"pending" }
});

JSON-only, kleines SDK oder drei HTTP-Endpunkte: propose → approve → complete. Krankenhäuser behalten FHIR, KMUs ihr ERP, Behörden ihre Fachverfahren. OpenAction liegt nur dazwischen.
