04 / PROOF, NOT PROMISES

Engineering you can question.

Hier sind nicht nur hübsche Kurven, sondern die Designentscheidungen, mit denen wir das System kontrollierbar halten.

Wie kommen echte Ergebnisse zustande?+

OpenAI Decisions nutzt POST /v1/decisions, Jev nutzt die OpenRouter Decisions API und das generative LLM die OpenAI Responses API mit Structured Outputs. Nur synthetische, serverseitig bekannte Ticket-IDs sind als Eingabe zulässig. Kostenpflichtige Aufrufe brauchen einen separaten Demo-Zugang.

Warum nicht einfach die beste Zahl auswählen?+

Die Evaluation ist multilabel-fähig. Entscheidend sind Macro-F1, Recall bei Produktqualität, übersehene Signale, Falschalarme und Review-Quote. Schwellenwerte dürfen nur auf Entwicklungs-/Validierungsdaten optimiert werden. Das Holdout wird einmal zum Abschluss ausgewertet.

Was ist heute nicht bewiesen?+

Es gibt weder reale Kundendaten noch einen abgeschlossenen Live-Modellbenchmark. Modell-Scores sind ohne Kalibrierung keine belastbaren Wahrscheinlichkeiten. Für echte Produktion brauchen wir ein verteiltes Rate Limit, Kostenbudget, Privacy Review, Monitoring und klare Freigaberegeln.
