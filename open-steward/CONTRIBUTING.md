# Contributing

Contributions are welcome.

1. Open an issue describing the problem and expected outcome.
2. Keep changes small and auditable.
3. Add or update eval cases for policy, approval, or orchestration changes.
4. Do not add secrets, personal data, or proprietary project material.
5. Run the unit tests and deterministic eval harness before opening a pull request.

Good first contributions include new project-manifest examples, policy tests, dashboard accessibility improvements, and read-only adapters.
