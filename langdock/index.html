01 / WHY LANGDOCK

The same problem has been pulling me here.

The most interesting challenge is no longer showing that AI can produce an impressive answer. It is building the abstractions, recovery paths, interfaces and trust that let entire organisations use AI every day. Langdock works directly on that gap between technical possibility and actual behaviour.

MODEL LAYER

Useful abstraction.

Provider quirks, structured output and fallback should disappear behind a reliable product contract.

AGENT LAYER

Bounded autonomy.

Agents need tools, context, iteration limits, confirmations and visible failure states.

WORKFLOW LAYER

Durable execution.

Long-running work must survive disconnects, provider failures and human pauses without duplicate side effects.

HUMAN LAYER

Calm interaction.

The system can be complicated underneath while the experience remains precise and understandable.

02 / THE PRODUCT AREA

Workflows excite me most.

Langdock Workflows sit at the exact boundary I want to work on: agentic and deterministic execution, hundreds of integrations, structured outputs, human approval, versioning and inspectable run history. They turn AI from a private chat habit into shared operational capability.

BUILD

Intent to explicit system.

Translate natural language into nodes, variables, tools and conditions without hiding what the workflow will actually do.

RUN

Resume without corruption.

Preserve tool-call integrity, pause for input and continue from exact state after a provider or user interruption.

UNDERSTAND

Make failure debuggable.

Use run history, costs, state transitions and actionable errors so builders and business users can improve safely.

04 / MOST INTERESTING PROJECT

GitLaw

LIVE · CLOSED-BETA PRO PILOT

I began with a simple question: can German law become genuinely navigable without letting an LLM invent authority? That became an end-to-end legal research and workflow platform where every answer must survive retrieval, generation and local citation verification.

5,936 laws98,367 vectors94,178 citation nodes53/53 citation evalsMCPFastAPI · React · TypeScript
WHAT WORKED

Separating retrieval, generation and verification made failures visible. The system can reject invalid paragraphs instead of presenting fluent nonsense as law.

WHAT DID NOT

Early versions optimised for a convincing answer rather than measurable trust. Hand-labelled evals and observability changed how I approach every AI system.
