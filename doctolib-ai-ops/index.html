01 · Context

What does the agent know?

Synthetic customer-success case: a clinic activation is delayed. The agent needs current account context, an implementation policy and recent support history before proposing a next action.

02 · Agent workflow

What may it do?

Interpretation is flexible; authority is not. The workflow can classify, retrieve, draft and prepare. CRM writes and customer communication remain review-gated.

03 · Evals

Would I trust it more?

The demo evaluates properties I would want before increasing autonomy. No invented production KPI uplift.

Baseline → redesigned workflow

Automate the low-judgement work. Preserve the hard decisions.

The goal is not “agent does everything.” The goal is to remove repetitive retrieval and drafting while making context freshness, failure modes, human decisions and measurement visible.

Before

  • Operator opens CRM, help docs and support history manually.
  • Context freshness depends on memory and tab-hunting.
  • Quality is reviewed case by case with weak feedback capture.
  • Impact is hard to separate from anecdotes.

After

  • Required sources are declared and checked before work starts.
  • Agent prepares a structured next-action package.
  • Eval failures become visible regression cases.
  • Human approval remains explicit for consequential writes.
