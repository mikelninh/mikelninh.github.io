02

Frontier AI should be benchmarked, not worshipped.

The role calls for deep Claude proficiency. My approach is practical: version the task contract, test models against the same frozen cases, separate structured-output validity from decision quality, and promote only when the failure profile improves.

A prompt is an operating contract.

For claims work I would keep the model’s job narrow and the surrounding policy deterministic.

TASK Classify the next operational action for one claim. CONTEXT • claim facts • retrieved policy clauses • missing-information flags • prior reviewer notes RULES • never invent policy language • abstain when evidence is insufficient • never perform payment / customer communication • explain which evidence supports the route OUTPUT { "route": "READY | REVIEW | NEED_INFO", "reason_codes": [...], "evidence_refs": [...], "confidence": 0.0-1.0, "uncertainty": "..." }

03

Make it work. Then make it run without you.

This is the part of the job description I like most. The end state is not “Mikel is good at fixing the queue”. The end state is a documented system with explicit quality gates, ownership and a review path.

01Observe

Process real work and map where decisions, waiting and rework happen.

02Specify

Define inputs, routes, failure modes, acceptance criteria and owner.

03Automate

Use models only where they remove repeatable cognitive/manual work.

04Prove

Frozen cases, edge cases, regression tests and human review metrics.

05Release

Start shadow/copilot; widen autonomy only when evidence earns it.

06Watch

Track drift, review reasons, cycle time and recurring failure clusters.

Quality gate

  • schema passes
  • no unsupported clause
  • uncertain cases route to review
  • gold cases stay green

Operator handoff

  • SOP + decision table
  • queue ownership visible
  • failure reason codes
  • prompt/model version logged

Scale signal

  • cycle time falling
  • review load explainable
  • rework clustered, not random
  • system survives my absence
