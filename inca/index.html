    02

    How I test whether a new model is actually better.

    A model release should not reach the workflow because it feels smarter. I would run the same frozen cases, measure the failure profile, and promote it only when the evidence improves.

    01

    Freeze cases

    Keep the same normal cases, edge cases and expected routes so the comparison is fair.

    02

    Run both versions

    Same task contract, same evidence, old model versus new model or prompt.

    03

    Measure failures

    Routing, abstention, grounding, schema validity, latency and cost.

    04

    Promote or reject

    No critical regression means it can move forward. Otherwise it stays out.

    What is still missing from this proof

    A real Claude benchmark run. I am deliberately not inventing model scores. The 12/10 version should include an executable Anthropic harness, a frozen holdout and real before/after evidence.

    03

    Fix the case. Then fix the system.

    The operator should not become the permanent workaround. Each recurring failure should become a clearer rule, better prompt, stronger test or better review process.

    01Observe

    Work the real queue and see where time, errors and rework appear.

    02Cluster

    Turn repeated edge cases into explicit failure reasons.

    03Improve

    Change the rule, prompt, retrieval or hand-off.

    04Prove

    Re-run frozen cases and regressions before release.

    05Watch

    Track review load, new failure clusters and cycle time.
