Architecture / proof
The operator observes the system, not just a final score.

  
Six developer-authored fictional claims from five claim types are processed by a real local Python tool executor. The supervisor only permits known tools and bounded input. Every tool response is recorded with source references.

  

    
01 · Actual tool use
Read → Extract → Compare
Two evidence reads, two fact extractions with quotes and hashes, one deterministic comparison, one unsent handoff draft. The supervisor records the outcome.
Inspect Python runner ↗

    
02 · Boundaries
Never trust a tool request blindly
An unknown tool, skipped step, missing evidence or invalid plan blocks automatic continuation. Suspicious instructions inside documents are handled by an independent guard.
Inspect safety regressions ↗

    
03 · Model independence
A planner can be replaced
The build uses an offline scripted planner. An optional, explicitly billable one-case OpenAI planning adapter is included, but no live-LLM result is claimed here. Planner choices never grant additional authority.
Read reproducibility guide ↗

  

  
Deliberately not production-ready: This is not live multi-agent inference, independently validated insurance adjudication, PDF/OCR, a customer data integration, expert approval, a deployed review queue or a payout workflow. The browser is a read-only playback of the Python build artifact. A real insurer pilot would require audited integrations, independently labelled cases and human-reviewed SOPs.
