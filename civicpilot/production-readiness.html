Production readiness

Not production-ready yet. Built to learn what production requires.

CivicPilot is a production-thinking prototype. It shows product direction, usefulness, and system awareness. The next version makes the gap explicit: what is shipped, what is missing, and what I want to learn from a team that takes AI products to production.

Honest status

Prototype, not product.

I do not want to pretend this is production-ready. The current version is a focused prototype for showing how I think: start with a painful workflow, define the AI assistant boundary, keep humans accountable, and map the path toward production.

What this should signal

I know the hard part is not making a polished AI demo. The hard part is user validation, workflow fit, reliability, risk, privacy, monitoring, and adoption. This is the gap I want to close by working with people who have shipped real applied-AI systems.

Readiness checklist

What is real, partial, and missing.

Done

Product concept, interactive workflow, positioning, pilot narrative, and application story.

Partial

Production path, risk awareness, human review model, KPI thinking, and architecture direction.

Missing

Real users, backend, database, authentication, structured AI outputs, evals, analytics, audit logs, monitoring, accessibility, and security review.

Learning

How an applied-AI team selects the right use case, runs the first pilot, handles risk, and decides when an AI product is ready for real users.

Target architecture

From concept page to working system.

Frontend

Next.js app

Intake form, report view, review queue, and usefulness feedback.

Backend

API layer

Structured generation, validation, persistence, and workflow orchestration.

Data

Postgres

Use cases, generated plans, feedback, audit entries, and user sessions.

AI

Structured output

Strict schemas, citations, confidence, refusal paths, and eval datasets.

Ops

Analytics + logs

PostHog events, error tracking, monitoring, and human override analysis.

Seven-day sprint

The next build.

The next version should stop being only a story and become a small working system: one real intake, one structured AI output, one saved report, one feedback loop.

Day 1

Talk to users

Interview three people with public-sector, admin, or ops workflow experience.

Days 2-3

Build structured AI output

Generate pilot plans as inspectable JSON: workflow, risks, MVP scope, KPIs, and human handoff.

Days 4-5

Persist reports

Add a database-backed report view with status, feedback, and version history.

Days 6-7

Measure usefulness

Add events for generated, approved, edited, rejected, downloaded, and marked useful.
