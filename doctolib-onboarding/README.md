Independent, synthetic role-fit work sample for technical onboarding / AI implementation.

## Product direction

The simulator is intentionally designed as a **playable miniature clinic**, not a conventional onboarding dashboard.

Core player loop:

1. **TALK** — clarify scope and operational context
2. **LOOK** — inspect logs, configuration, data and infrastructure
3. **TRY** — run targeted tests and fallbacks
4. **CONTAIN** — reduce blast radius before full certainty
5. **CALL IT** — commit root cause + permanent fix
6. **DEBRIEF** — review diagnosis, safety, efficiency and communication
7. **DOSSIER** — automatically turn the run into structured proof-of-work

The flagship vertical slice is **Broken Calls**.

It includes:
- a living miniature clinic world,
- patient queue pressure,
- clinic trust and operational risk,
- interactive system rooms,
- visible end-to-end signal tracing,
- collectible clue cards,
- evidence-combination / AHA moments,
- proportionate containment,
- intentionally tempting wrong actions,
- optional generated UI sound,
- four-star mission clear,
- replay variants with the same symptom but different hidden causes,
- shareable interview-mode links,
- automatic case-dossier generation,
- local run history and skill tracking in the Academy,
- reflection + portfolio-ready evidence gating.

## Design principle

> **Easy to enter. Delightful to touch. Deep enough to master.**

The visual aspiration is console-grade clarity and tactile joy, while remaining fully original. The game does not copy proprietary characters, layouts, sounds or assets.

See `GAME_DESIGN_BIBLE.md` for the full game-design, art-direction, interaction, sound, character, progression and vertical-slice specification.

## Professional skills represented

- technical preflight,
- API / network / VPN reasoning,
- call-routing investigation,
- migration data-quality validation,
- go-live gating,
- incident containment,
- fallback / rollback thinking,
- evidence-based root-cause analysis,
- stakeholder communication,
- documentation and handoff.

## Boundaries

The project is company-neutral and contains **no Doctolib, customer or patient data**, no copied product UI, and no production integration claims.
