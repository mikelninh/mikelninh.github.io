Technischer Kern

Mein aktuelles Mental Model.

Ich wollte modellieren, was solche Systeme vertrauenswürdig macht: nicht Magie im Prompt, sondern getrennte Bausteine, die man prüfen und verbessern kann.

01

Source Registry

Quellen mit URL, Amt, Status, Review, Aktualität und Vertrauenslevel.

02

Importer

URL/Text wird extrahiert, in Chunks vorgeschlagen und nie blind veröffentlicht.

03

Retrieval

Fragen werden gegen freigegebene Chunks gesucht. Confidence ist Trefferstärke, kein Wahrheitswert.

04

Serviceflow

Antwort, Routing, Termin, Ticket, Rückruf oder Handoff werden vorbereitet.

05

Receipt

Jeder Vorgang wird menschenlesbar und maschinenlesbar nachvollziehbar.

06

MCP Tools

Agents könnten später dieselben Tools nutzen: import_source, search_sources, classify_statement, create_receipt.

Truth / Text Analyzer

Worüber streiten wir eigentlich?

Das ist eine Nebenidee, die mich schon länger beschäftigt: Aussagen sauberer trennen. Fakt, Wert, Gefühl, Glaube, Prognose. Für Bürgerkommunikation, interne Diskussionen und Agents kann das extrem hilfreich sein.

Wenn ich weiterbauen würde

Die nächsten echten Engineering-Schritte.

1. Persistente Source Registry

Postgres/Supabase statt LocalStorage. Quellen, Chunks, Reviews, Owner, Versionshistorie.

2. Real MCP Server

Ein kleiner Server mit Tools für Import, Suche, Klassifikation, Action Payloads und Receipts.

3. Embeddings + Eval

Vector Search sobald mehrere echte Quellen vorliegen; Eval verhindert Regressionen.

4. Integrationen

Kalender, Ticketing, Rückrufsystem und Analytics als austauschbare Adapter.
